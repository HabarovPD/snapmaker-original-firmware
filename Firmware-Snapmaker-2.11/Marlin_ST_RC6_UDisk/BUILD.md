# Сборка GCC и прошивка через ST-Link V2

Оригинальный проект IAR (`*.ewp`) в архив не попал, его съел `.gitignore`.
Вместо него здесь `Makefile` под `arm-none-eabi-gcc`, прошивка через OpenOCD.

## Инструменты (MSYS2)

```
pacman -S mingw-w64-ucrt-x86_64-arm-none-eabi-toolchain mingw-w64-ucrt-x86_64-openocd make
```

Нужен драйвер ST-Link: STSW-LINK009 от ST, либо WinUSB через Zadig.

## Сборка

```
export PATH=/c/msys64/ucrt64/bin:/c/msys64/usr/bin:$PATH
make -j8              # MCU=F103 по умолчанию
make -j8 MCU=F105     # родной чип
```

| `MCU` | Чип | Отличия |
|-------|-----|---------|
| `F103` (по умолчанию) | GD32F103RE / STM32F103 HD (поставлен при замене) | кварц 16 МГц → PLL HSE/2·9 = 72 МГц; **USB-хоста нет**: печать и обновление с флешки отключены (`CFile/UDiskNone.c` отвечает «флешка не вставлена») |
| `F105` | STM32F105RC / GD32F105RC (заводской) | полный функционал, плюс `Update.Bin` |

Результат лежит в `build/<MCU>/`:
- `app.bin` — образ приложения для адреса `0x08009800`;
- `Update.Bin` (только F105) — тот же образ с заголовком для обновления с флешки
  через штатный загрузчик.

## Карта flash (STM32F105RC / GD32F105RC, 256K)

| Адрес        | Размер | Что                                         |
|--------------|--------|---------------------------------------------|
| `0x08000000` | 32K    | загрузчик Snapmaker (в исходниках его НЕТ)  |
| `0x08008000` | 6K     | параметры загрузчика                        |
| `0x08009800` | 128K   | Marlin (эта сборка)                         |
| `0x08029800` | 4K     | настройки Marlin (эмуляция EEPROM)          |

## Прошивка ST-Link V2

Подключение к SWD-разъёму платы: SWDIO, SWCLK, GND. 3.3V подключать только как
опорное напряжение, сам принтер питать от своего блока.

### Новый / заменённый чип (загрузчика Snapmaker нет)

```
make probe
make flash-blank   # заглушка на 0x08000000 + прошивка на 0x08009800
```

Настройки (шаги, PID, смещения) при первом старте берутся по умолчанию,
потому что область `0x08029800` пустая. Дальше их задают через `M500`.
Обновление с флешки (`Update.Bin`) без родного загрузчика не работает,
обновлять нужно через ST-Link: `make flash`.

### Чип с родным загрузчиком

```
make probe     # видит ли чип, включена ли защита чтения (RDP)
make backup    # ОБЯЗАТЕЛЬНО до первой записи: backup/flash_full.bin
make flash     # пишет только 0x08009800..; загрузчик и настройки не трогает
make restore   # вернуть всё как было из backup/flash_full.bin
```

Никогда не делайте `mass erase` / "Full chip erase": так стирается загрузчик,
а его исходников нет.

Если чип защищён от чтения (RDP), снять защиту можно только вместе со стиранием
всего флеша, включая загрузчик. После этого:

```
make flash flash-stub
```

`flash-stub` записывает на `0x08000000` 32-байтную заглушку, которая сразу
передаёт управление прошивке. Обновление с флешки после этого работать не будет,
обновлять придётся через ST-Link.

## Отличия от IAR-сборки

- Весь прикладной код и USB-стек компилируются как C++, как это делал IAR.
- `SaveSR/RestoreSR` переписаны на интринсики CMSIS: IAR-asm с `bx lr`
  после инлайна в GCC ломал критические секции.
- В `delay_us` (I2C лазерного модуля, `Laser.cpp`) счётчик сделан `volatile`,
  иначе GCC выкидывает цикл задержки.
- `SDCard/cardreader.cpp` не собирается: в проекте используется `UDisk`.
